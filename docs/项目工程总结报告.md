# common-free 项目工程总结报告

## 1. 项目概况

`common-free` 将教务课表同步、本地目录管理和教师公共空闲计算放在一个 Node.js 22 服务中。服务端使用 TypeScript、Fastify 与 `node:sqlite`，前端使用 Vue 3。生产依赖为 `fastify`、`jpeg-js`、`vue`，数据库不经过 ORM。

生产启动后由一个 Fastify 端口同时提供 `dist/` 和 `/api`；本地默认监听 `127.0.0.1:3000`，Docker 使用 `0.0.0.0`。Docker 使用 `node:22-slim` 两阶段构建，Compose 将数据目录和环境文件挂载到容器。

## 2. 重构对照

| 方面 | 旧系统 | common-free |
|---|---|---|
| 后端形态 | Spring Boot + MySQL | Node.js 22 + TypeScript + Fastify |
| 前后端交付 | 独立的服务与页面部署 | 一个端口同时提供静态资源与 API |
| 数据访问 | MySQL 及其服务端配置 | 原生 `node:sqlite`，文件为 `data/app.sqlite` |
| 查询目标 | 以教务数据管理为主 | 聚焦多位教师的公共空闲计算 |
| 课表来源 | 依赖既有导入流程 | 学院逐页同步，并以全校总表兜底 |
| 运行部署 | 传统应用服务 | `node:22-slim` 两阶段 Docker 镜像 |

这里的对照描述架构取舍，不包含未经测量的性能或内存结论。

## 3. 三个实现难点

### 3.1 真实滑块协议与登录状态

登录流程需要先从页面取得 salt，再使用 AES 处理密码；需要滑块时，前端展示固定 300×150 的轨道。提交给服务端的 `canvasWidth` 是轨道的 `clientWidth`，`move` 是实际拖动距离，轨迹点一并提交。

实现过程中曾尝试将图片相关尺寸从 590 像素缩放到 280 像素，但该方向被放弃，不能作为最终协议。最终实现以真实轨道尺寸和拖动距离为契约。Cookie 也不因单次校验通过就立即缓存，而是等教师页真正含有 `xnxqh` 且标题不是登录页后再写入缓存。

### 3.2 学院数据与全校总表兜底

仅遍历学院页可能遗漏不在学院页呈现的教师。因此同步先读取教师页和学院列表，再逐学院拉取课表，最后额外拉取一次全校总表。总表中已经出现在学院结果里的教师跳过；只在总表出现的教师标记为 `UNAFFILIATED`（未分院系）。

当前教务页夹具包含 13 个学院，任务进度因此按 13+1 计算。学期替换在 `replaceSemester` 中用 `BEGIN`、`COMMIT`、`ROLLBACK` 保证失败时不留下半套数据。

### 3.3 不同学期的课表列数

旧学期没有 `1112`，一行课表为 36 个单元格；新学期有六节，节次表头为 `0102 0304 0506 0708 0910 1112`。解析器先读取第二行表头：当每天节次连续时，按实际列数计算每天的节次，而不是套用固定列数，从而兼容两个学期形态。

## 4. 多智能体协作分工

- 主架构师：定义模块边界、API 与数据契约，协调同步状态和前后端接口。
- worker：实现后端，包括 Fastify 路由、SQLite 数据访问、教务登录与课表同步。
- ui-worker：实现 Vue 界面、教师选择、同步进度和公共空闲展示。
- reviewer：审查 diff，重点检查安全边界、错误处理、数据覆盖和契约一致性。

测试使用 Node 原生 `node:test`；仓库测试文件共包含 51 个 `test()`。代码改动后不只运行自动化测试，还要查看真实页面或调用真实接口，确认文档与实际行为一致；本文不编造响应毫秒数、吞吐量或内存数字。

## 5. 验证与边界

可执行的基础检查包括 `npm test`、`npm run build` 和 `npm run typecheck`。生产构建后使用 `npm start`；Docker 场景使用 `docker compose build`、`docker compose up -d` 和 `docker compose ps`。

公开仓库不应包含真实账号、密码、Cookie 或本地环境文件。`.env.local.example` 仅提供域名占位符，Cookie 缓存目标权限为 `0600`，运行数据与构建产物按 `.gitignore` 排除。
